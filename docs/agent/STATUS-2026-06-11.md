## Completed

### The cache mystery (yesterday's open question) — resolved
The 30-second discriminating experiment settled it: **preview render ≡ published
render** for the same theme (byte-identical JSON-LD blocks, including Shopify's
platform-injected Organization on both). The "stale snowboard pages" were
Shopify's storefront page cache serving pre-publish copies for minutes-to-hours,
converging page by page, with fresh-looking headers and unreliable response to
cache-buster params. Theories "preview is structurally blind" and "missed
template sections" are dead.

### Bugs the browser QA found (both fixed + unit-tested + proven live)
- **SSE death kills live runs.** Two long applies died at ~165s/~300s (idle gap
  during theme duplicate; Node `requestTimeout`-shaped cutoff), and the route
  treated the dead socket as a kill — aborting Shopify work mid-duplicate and
  orphaning a half-copied theme (the duplicate's own cleanup deleted it). Fixed
  three ways (heartbeat / disconnect≠kill / poll fallback).
- **Subset-run snippet clobbering.** A 2-URL run rewrote the snippet from its own
  entries, silently wiping the third product's schema while theme emitters stayed
  suppressed — page went to ZERO structured data. L3 no-regression structurally
  can't catch this (the page isn't in the run's set). Fixed by merge-not-replace;
  the 3-URL follow-up run restored the page.

## Blockers / open issues

1. **Dev-store cache convergence (env quirk, not a product bug).**
   `verify-live-final.ts` currently FAILs `the-3p-fulfilled-snowboard` because some
   cache nodes still serve the pre-fix render (cached during the regression window),
   even though post-publish verification saw the staged blocks on fresh renders and
   the theme asset provably contains the entry. Expect convergence; re-run later.
   QA-POC-E2E.md §4 explains how to read this.
2. **Result card doesn't survive a page reload.** The run completed but a remount
   wiped the in-memory result; the runner has no "rehydrate last run" on mount.
   Data is all in the DB (report page + audit rows) — UX gap only.
3. **Report "Required actions" copy is stale/wrong after a published run.** It said
   "Apply the run live: 1 page has verified fixes that are previewed only" and
   "your theme or an app still emits the original structured data on 3 pages" on a
   run that *was* published with suppressions verified by the dup gate. The verdict
   header is right; the required-actions derivation needs a look.
4. **LLM emits `priceValidUntil` in the past** (2025-12-31 on a 2026 run). Gates
   accept it; Google may warn. Needs a validation rule (deterministic, in
   lib/validation) or prompt nudge.
5. **Tweak panel not yet exercised in this browser pass** (Flow A step 3). It was
   proven live at the library level previously (sticky across regeneration), but
   the UI path deserves the same browser treatment.
6. **garnerandtow one-shot still pending** real-store credentials (the point of the
   POC). Everything it needs is now in place and rehearsed.
